# приложение для подбора вина

приложение загружает готовую модель из третьей части, обучение внутри приложения не выполняется

проверено на python 3.12.14, для локального запуска и облака используй python 3.12

## состав папки

- `app.py` содержит интерфейс и кэширование
- `wine_utils.py` содержит проверку csv и расчет метрик
- `model.joblib` содержит весь обученный пайплайн
- `config.json` содержит выбранный на валидации порог
- `test.csv` содержит тестовые данные и целевую переменную
- `requirements.txt` фиксирует проверенные версии библиотек

## локальный запуск в windows

открой терминал в папке `wine_app`, создай отдельное окружение и установи зависимости

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

если команды `py` нет, используй путь к установленному python 3.12 вместо `py -3.12`

после запуска открой адрес из терминала, обычно это http://localhost:8501

## локальный запуск в linux или macos

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

## как устроены задания четвертой части

вкладка одно вино содержит одиннадцать числовых полей и переключатель типа вина, начальные значения и границы взяты из тестовой таблицы

вероятность сравнивается с общим порогом в боковой панели, начальный порог загружается из конфигурации

вкладка модельные метрики показывает матрицу ошибок, precision, recall и f1, красные точки на roc и pr кривых соответствуют текущему порогу

при увеличении порога подборка становится меньше и обычно точнее, при уменьшении порога растет полнота и число ошибочных рекомендаций

вкладка пакетный прогноз принимает csv с двенадцатью исходными признаками, позволяет скачать пример и результаты

если не хватает столбцов или встречаются пропуски и нечисловые значения, приложение показывает понятную ошибку

вкладка что выучила модель показывает отсортированные коэффициенты после стандартизации, положительные и отрицательные связи подписаны отдельно

порог на тестовой выборке здесь меняется для демонстрации компромисса метрик, выбирать новый производственный порог по этому тесту нельзя

## почему используются два вида кэша

`st.cache_resource` хранит один экземпляр модели, он используется повторно при действиях пользователя и между сеансами

для модели нужен именно общий ресурс, повторно читать и десериализовывать файл при каждом движении ползунка не требуется

`st.cache_data` подходит для таблиц и массивов, результаты вычислений сохраняются, а вызывающий код получает отдельную копию данных

тестовая таблица и вероятности кэшируются отдельно, при движении ползунка повторяется только сравнение вероятностей с порогом и расчет метрик

аргумент `_model` не участвует в хэшировании, вместо него в ключ добавляется версия файла модели, поэтому замена файла сбрасывает старые результаты

без декоратора вокруг функции с `joblib.load` файл читался бы и модель создавалась бы заново при каждом перезапуске скрипта
